# DataForge product UI redesign specification

**Status:** Proposed product-wide design contract. Left sidebar resizing and the Notebook Home refinement are implemented; native interaction verification remains pending. **Direction:** Hybrid + Balanced. This document refines [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md) and [UX_SPEC.md](UX_SPEC.md). ADR 0010's repository-owned Base UI/shadcn foundation and semantic tokens remain authoritative. Resolve any changed token or shared-component rule in `DESIGN_SYSTEM.md` before implementing it across screens.

## 1. Product and visual rules

DataForge is a local investigation workspace. Chat, Notebook, Dashboard, sources, and inspector are views of the same project and evidence. Use a polished, quiet shell, technical density where data needs it, and conversation only where it helps investigation. Preserve the left navigation/sources, central workspace, contextual right inspector, and bottom composer arrangement in Chat; Notebook collapses Threads within that shared sidebar so Sources fills it, while Inspector and composer leave the Notebook workspace as [UX_SPEC.md](UX_SPEC.md) requires. Dashboard should reuse the shell and shared investigation state when implemented.

Use the existing charcoal semantic palette: app background, sidebar, surface, elevated surface, hover, selected, border, text, status, and focus roles. Prefer one-pixel dividers and surface changes to card borders and shadows. Use elevated surfaces for menus, popovers, and dialogs, not every content block. Do not add untracked colors. Check text, muted text, and focus contrast on the actual target surfaces before changing token values. Status always has a label or icon in addition to color.

## 2. Global typography, spacing, and controls

| Role | Target |
| --- | --- |
| UI copy, navigation, labels, buttons, chat | Proportional `--font-family-ui`: Inter when supplied, then Segoe UI, Arial, sans-serif. Do not use a Nerd Font for ordinary prose. |
| Code, SQL, Python, paths, identifiers, technical values | `--font-family-code`: packaged **JetBrainsMono Nerd Font**, then locally installed `JetBrainsMono Nerd Font`, Cascadia Code, Consolas, monospace. Use regular and medium/bold weights only when corresponding files are packaged. |
| Title / section / component / body / secondary / metadata / code | Start with current 30 / 20 / 13 / 12 / 11 / 10 / 12 px tokens. Notebook document prose may use the existing 13 px component role; test readability at 100%, 125%, and 150% Windows scaling before changing global sizes. |
| Spacing | Existing 4 px scale, `--space-1` through `--space-12`. Default control x padding 12 px, panel inset 16 px, section gap 24 px, page inset 32 px; narrow page inset 16 px. Use 1–2 px only for optical alignment and borders. |
| Radius | Existing 3 px small, 4 px default, 8 px large, pill only for pill shapes. No new per-screen radii. |
| Standard controls | Shared `Button`: 28 / 36 / 44 px small/default/large, 12 px horizontal padding; shared `IconButton`: 28 × 28 px. Use 16 px control icons, 14 px dense icons, 20 px prominent icons. Shared Input/Select: 36 px; dense notebook cell Select: 28 px. |

The [JetBrains Mono upstream page](https://www.jetbrains.com/lp/mono/) identifies SIL Open Font License 1.1, and the [Nerd Fonts JetBrainsMono page](https://github.com/ryanoasis/nerd-fonts/blob/master/patched-fonts/JetBrainsMono/README.md) identifies its patched variants and bundled glyph sources. The [Nerd Fonts license](https://github.com/ryanoasis/nerd-fonts/blob/master/LICENSE) permits embedding/redistribution subject to its terms. Before adding files, verify the exact selected release's family names, weights, included licenses, and attribution. Package the needed font files with frontend assets so Windows users need no system installation; load via `@font-face`. Use `font-display: swap` and the fallback stack to avoid blocking the UI. Check common code glyphs, box drawing, and ordinary punctuation in WebView2 at Windows scaling. No font file is currently packaged; this is a target, not an implemented claim. If asset licensing or rendering validation fails, retain the present code fallback until resolved.

All recurring buttons, inputs, selects, menus, dialogs, popovers, and tooltips use `components/ui/`. Contextual controls may be compact only when their hit area, focus treatment, and label are clear; standard actions use shared size variants. A new repeated pattern must first be recorded in `DESIGN_SYSTEM.md` and shared foundation. The mode selector stays a button group with `aria-pressed`, not tabs, as ADR 0010 explains.

## 3. Application shell

### Layout and sidebars

The shell owns left sidebar width, optional inspector width, and central available width. Use a grid whose tracks reflect live sidebar dimensions; the central track is `minmax(0, 1fr)`. Never allow a resized sidebar box to overflow an unchanged grid track. Centre each workspace content column within **its remaining central track**, not the entire window. Data tables and wide analytical results may use the full central track and scroll internally; prose and Notebook cells use a readable max width of approximately 1,120 px. Both edges of the central track should have equal free space when content is narrower than that track.

Give the left sidebar a full-height inner-edge resize target with a visible one-pixel separator and an approximately 8 px pointer hit area. Its grab cursor should appear anywhere along the edge. Start at 248 px; allow 210–340 px. The right inspector starts at 270 px and should be collapsible; if resizing it is added, use the same edge rule and a roughly 240–360 px range. Avoid a corner-only CSS resize affordance. Persist the left width as a local application layout preference and clamp restored values to its allowed range. Keyboard resizing must have an equivalent operable control or documented key handling, visible focus, and announced value. Double-click/keyboard reset may restore the default. Vertical Threads/Sources division can keep a separate resizer, but must have a clear horizontal hit area and bounded heights.

The top bar owns project identity, project actions, and **one** inspector toggle. Remove the workspace-toolbar duplicate. Keep the mode switcher at the top centre of the application content, in a stable shell-owned position independent of breadcrumb or action widths and sidebar changes. It must not shift when project text changes, a sidebar opens, or the mode changes. Reserve enough non-overlapping space for project identity and window controls; truncate project text first. Use the existing compact group styling and selected/focus states. The central toolbar may show breadcrumbs and mode-specific actions, but it does not own mode positioning.

### Custom Windows title bar

Target one 40–48 px DataForge title bar replacing the native caption only after the Windows integration is proven. Left: DataForge mark/name and project context. Centre: fixed mode switcher. Right: project actions, inspector toggle where relevant, then minimize, maximize/restore, and close controls. Give caption controls at least a 36 × 36 px operable target while keeping icon geometry consistent with the shared foundation. Control names and state must be accessible; show maximize versus restore accurately. Keep a sufficient blank draggable region; interactive descendants must not initiate dragging. Support double-click on blank caption space to maximize/restore, keyboard access, and unsaved Notebook close protection. Native edge/corner resize, maximized work area, DPI scaling, multi-monitor movement, and Windows Snap must be validated before removing native decorations from the shipped window. Tauri permissions must be limited to the needed window operations. Hiding decorations alone does not supply these behaviors.

### Narrow windows

At widths near the current 900 px native minimum, collapse the inspector first; do not merely hide it while leaving an allocated grid track. Let the left sidebar narrow to its minimum or collapse in Notebook, then give the central track all remaining width. Toolbar actions may move into a menu or wrap where the existing Notebook toolbar already does, while the mode selector remains in its fixed top-centre slot. Do not overlap title bar controls. Keep the Notebook editor and table scroll areas usable at 900 × 600 and at 125%/150% Windows scaling. Document any breakpoint in the shell tokens/contract rather than scattering overrides. The current CSS root minimum of 760 × 520 and Tauri minimum of 900 × 600 need one deliberate policy during implementation.

## 4. Chat workspace

The left sidebar contains conversation history above Sources once an agent integration exists. Today, Threads is an honest unavailable state; do not fabricate selectable conversations. The central Chat content uses a readable column, approximately 720–820 px for prose, centred in the available track. Messages have clear role, timestamp/status where useful, and restrained separators rather than a card around every turn. Distinguish user messages, agent responses, tool activity, and analytical results by label, icon, structure, and semantic color. Tool details are expandable with a concise summary; analytical results link to source, execution, and evidence. Keep code and tabular output monospaced where appropriate. The bottom composer stays anchored to the central track, with attached data/context chips and disclosure status visible when those capabilities exist. The current disabled composer must continue to say agent work is unavailable until integration is real. Do not imply an upload, active provider, or hidden execution.

## 5. Notebook workspace

Notebook mode keeps the shared sidebar while Threads collapses and Sources rises to fill its space; the transition honors reduced motion. Home uses a small primary New Notebook action aligned with the title and adjacent compact search/sort controls before its resource list. The editor owns the central area and scrolls its document independently beneath a clear, sticky title/toolbar. Preserve project-scoped Home, existing SQLite blocks, draft protection, selection/command/edit modes, and saved result replay. Use a continuous document column up to approximately 1,120 px, with 16–32 px side gutters depending on width. Cells use quiet separators and compact 8–16 px internal rhythm; show selection with the existing accent edge and focus separately. A selected preview Code or Text cell shows a contextual Edit action. Boundary Code/Text insertion actions appear on hover or keyboard focus, without a tall permanent gap or persistent controls around a selected cell. Cell menu actions use the shared menu; toolbar actions use standard button heights. Preserve Code and Markdown cells, language metadata, source editor, and output directly beneath its cell. Code cells show an unrun prompt and an explicit unavailable state; no Run control, execution count, spinner, or fake output until a runtime exists. Saved analytical Result cells show provenance and bounded replay/unavailable states. Up/Down, Enter, Escape, A/B, D D, Shift+Enter, Ctrl+Enter, and Ctrl+S retain current documented semantics. Wide result tables scroll horizontally within the document rather than widening the shell.

## 6. Future Dashboard workspace

Dashboard is currently an empty state. When implemented, use the same shell, sidebar, mode position, inspector, token hierarchy, and evidence links. Use the central track for responsive charts/tables, with a readable title and compact toolbar; let selected artifact configuration appear in the contextual inspector. Show data alternatives for charts. Do not introduce a separate dashboard UI library, unrelated state model, or fake charts in this redesign phase.

## 7. Accessibility and motion

Every icon-only action has an accessible name and visible focus. Preserve native input/select semantics and Base UI menu/dialog focus behavior. Resizers support pointer and keyboard, announce the pane and current width, and never trap focus. The mode group reports selection with `aria-pressed`; active mode remains distinguishable without color. Keep minimum usable hit areas in dense regions; keyboard and screen-reader access must cover cell actions and disclosures. Use the existing short 120 ms hover/focus transitions, no layout motion for selection or resizing, and disable nonessential transitions under `prefers-reduced-motion: reduce`. Do not animate analytical data in a way that obscures exact values.

## 8. Implementation gate

This specification records targets and implementation gates. Task 1.1 supplies the shared left width and edge resizer; its native interaction check remains open. Continue in stages: workspace positioning (Task 1.2); fixed mode placement and duplicate-control removal; native custom chrome with Windows verification; shared control cleanup and font packaging; Notebook refinement; Chat presentation when real conversation state exists; Dashboard when its data model exists. Preserve analytics, persistence, and Tauri command contracts. Update `DESIGN_SYSTEM.md` and any affected UX/ADR contract when implementation choices are accepted.
